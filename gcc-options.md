# Настройки и опции компилятора GCC

Этот файл описывает основные группы опций компилятора `gcc` с примерами и пояснениями. Полный список всегда можно получить командой:

```bash path=null start=null
gcc --help
man gcc
``` 

## Базовый вызов gcc

```bash path=null start=null
gcc [опции] файлы.c -o программа
```

Главная идея: вы указываете исходные файлы, желаемое имя выходного файла (`-o`) и набор опций, влияющих на компиляцию и линковку.

---

## 1. Настройки стандарта языка C/C++

Используются для выбора версии стандарта и совместимости.

- `-std=c89`, `-std=c99`, `-std=c11`, `-std=c17`, `-std=c23`  
  Выбор стандарта C.

- `-std=gnu11`, `-std=gnu17` и т.п.  
  То же, что и соответствующий стандарт C, но с GNU‑расширениями (по умолчанию часто `gnu11`).

- Аналогично для C++: `-std=c++11`, `-std=c++14`, `-std=c++17`, `-std=c++20`, `-std=gnu++17` и т.д.

**Пример:**

```bash path=null start=null
gcc -std=c11 main.c -o app
```

---

## 2. Оптимизация кода

Опции семейства `-O` управляют компромиссом между скоростью, размером и временем компиляции.

- `-O0`  
  Без оптимизации (по умолчанию в debug‑сборках). Упрощает отладку.

- `-O1`  
  Базовая оптимизация без резких компромиссов.

- `-O2`  
  Более агрессивная оптимизация. Часто используется по умолчанию для релизных сборок.

- `-O3`  
  Максимальная общая оптимизация (возможен рост времени компиляции и размера бинарника).

- `-Os`  
  Оптимизация под размер бинарника (минимизация кода).

- `-Ofast`  
  Очень агрессивная оптимизация, может нарушать строгие требования стандарта (например, к арифметике с плавающей точкой).

**Пример (релизная сборка):**

```bash path=null start=null
gcc -O2 main.c -o app
```

---

## 3. Диагностика и предупреждения

Опции предупреждений помогают находить ошибки и потенциальные проблемы.

### 3.1. Общие уровни предупреждений

- `-Wall`  
  Включает «основной» набор полезных предупреждений.

- `-Wextra`  
  Дополнительные (более строгие) предупреждения.

- `-Wpedantic` или `-pedantic`  
  Предупреждать о нарушениях стандарта (особенно при использовании `-std=c11` и т.п.).

- `-Werror`  
  Превращать все предупреждения в ошибки компиляции.

- `-Wno-<name>`  
  Отключить конкретное предупреждение, например: `-Wno-unused-parameter`.

**Пример (строгая компиляция):**

```bash path=null start=null
gcc -std=c11 -Wall -Wextra -Wpedantic -Werror main.c -o app
```

### 3.2. Часто используемые специфичные предупреждения

- `-Wshadow` — переменная скрывает (shadow) другую с тем же именем.
- `-Wfloat-equal` — сравнение чисел с плавающей точкой через `==` / `!=`.
- `-Wcast-align` — небезопасное выравнивание при приведении указателей.
- `-Wpointer-arith` — подозрительная арифметика указателей.
- `-Wswitch-enum` — `switch` по enum без обработки всех значений.
- `-Wunused-variable` / `-Wunused-function` / `-Wunused-parameter` — неиспользуемые сущности.

## 4. Отладка

Опции для генерации отладочной информации и управления поведением кода при отладке.

- `-g`, `-g1`, `-g2`, `-g3`  
  Встраивает информацию для отладчика (например, `gdb`). Уровень (`1–3`) управляет детализацией.

- `-ggdb`  
  Информация, оптимизированная под `gdb`.

- `-fno-omit-frame-pointer`  
  Не удалять указатель кадра стека — упрощает анализ стек‑трейсов.

- `-fsanitize=address`  
  Включает AddressSanitizer: поиск выходов за границы массивов, use‑after‑free и др.

- `-fsanitize=undefined`  
  UndefinedBehaviorSanitizer: обнаружение неопределенного поведения.

- `-fsanitize=thread` и др.  
  Другие санитайзеры (гонки потоков, и т.п.).

**Пример (debug + ASan):**

```bash path=null start=null
gcc -g -O0 -fsanitize=address main.c -o app
```

---

## 5. Управление файлами, путями и инклудами

### 5.1. Пути к заголовочным файлам

- `-I<путь>`  
  Добавить путь к пользовательским заголовочным файлам. Можно указывать несколько раз.

```bash path=null start=null
gcc -Iinclude -Isrc/headers main.c -o app
```

### 5.2. Пути к библиотекам и их подключение

- `-L<путь>`  
  Добавить путь поиска библиотек при линковке.

- `-l<имя>`  
  Подключить библиотеку `lib<имя>.a` или `lib<имя>.so` (в зависимости от платформы).

**Пример:**

```bash path=null start=null
gcc main.c -L/usr/local/lib -lmylib -o app
```

### 5.3. Управление только компиляцией / только линковкой

- `-c`  
  Компилировать в объектный файл (`.o`), не выполняя линковку.

- `-S`  
  Генерировать ассемблерный код (`.s`) вместо объектного.

- `-E`  
  Выполнить только препроцессинг и вывести результат в stdout.

**Примеры:**

```bash path=null start=null
gcc -c main.c         # получим main.o

gcc -S main.c         # получим main.s (ассемблер)

gcc -E main.c > main.i # только результат препроцессора
```

## 6. Препроцессор (макросы)

- `-DNAME`  
  Определить макрос `NAME` со значением `1`.

- `-DNAME=VALUE`  
  Определить макрос `NAME` со значением `VALUE`.

- `-UNAME`  
  Удалить (undef) макрос `NAME`, если он был определен.

**Пример (разные конфигурации сборки):**

```bash path=null start=null
gcc -DDEBUG main.c -o app_debug

gcc -DNDEBUG main.c -o app_release
```

В коде можно использовать:

```c path=null start=null
#ifdef DEBUG
    printf("Debug info\n");
#endif
```

## 7. Управление линковкой

- `-static`  
  Просить статическую линковку (там, где доступно).

- `-shared`  
  Собрать разделяемую библиотеку (Unix: `.so`, macOS: `.dylib`/`.so`).

- `-pie` / `-no-pie`  
  Включить / отключить позиционно‑независимый исполняемый файл.

- `-Wl,<опция>`  
  Передать опции напрямую компоновщику `ld`. Например: `-Wl,-rpath,/usr/local/lib`.

**Пример (общая библиотека):**

```bash path=null start=null
gcc -shared -fPIC -o libmylib.so mylib.c
```

## 8. Управление ABI и генерацией кода

Эти опции специфичны для архитектуры и платформы.

- `-m32`, `-m64`  
  Сборка 32‑ или 64‑разрядного кода (если поддерживается платформой).

- `-march=<арх>`  
  Оптимизация под конкретную архитектуру CPU (например, `-march=native`, `-march=armv8-a`).

- `-mtune=<арх>`  
  Настройка под конкретный CPU для лучшей производительности, не ломая совместимость с другими.

- `-fPIC` / `-fpic`  
  Генерировать позиционно‑независимый код (для разделяемых библиотек).

- `-fno-exceptions`, `-fno-rtti` (для C++)  
  Отключение исключений и RTTI (может уменьшить размер кода).

---

## 9. Стандарты и проверки времени выполнения

- `-fstack-protector`, `-fstack-protector-strong`, `-fstack-protector-all`  
  Защита стека от переполнения буфера.

- `-fno-strict-aliasing`  
  Ослабление предположений об aliasing указателей (иногда нужно для старого кода).

- `-fstrict-aliasing`  
  Включает оптимизации, предполагая строгие правила aliasing (по умолчанию с `-O2`).

- `-fno-builtin` или `-fno-builtin-<имя>`  
  Запрет компилятору рассматривать стандартные функции как встроенные (например, `-fno-builtin-memcpy`).

---

## 10. Работа с профилированием

- `-pg`  
  Встраивает код для профилировщика `gprof`.

- `-fprofile-generate` / `-fprofile-use`  
  Профилируемая оптимизация (PGO): сначала собираете с `-fprofile-generate`, запускаете программу с типичной нагрузкой, затем пересобираете с `-fprofile-use`.

---

## 11. Управление языковыми расширениями

- `-fno-gnu89-inline` и подобные  
  Управление поведением `inline` и другими особенностями старых стандартов.

- `-fms-extensions`  
  Поддержка некоторых расширений Microsoft (C/C++).

- `-ansi`  
  Включает строгий ANSI C (то же, что примерно `-std=c89 -pedantic`).

---

## 12. Вывод, логирование и сбор информации

- `-v`  
  Подробный вывод того, что делает компилятор (какие стадии запускаются, какие файлы ищутся и т.д.).

- `-ftime-report`  
  Печатает, сколько времени заняла каждая стадия компиляции.

- `-Q`  
  Показывает, какие именно внутренние опции включены.

**Пример:**

```bash path=null start=null
gcc -v -O2 main.c -o app
```

---

## 13. Типичные профили сборки

### 13.1. Debug‑сборка

Цели: простая отладка, максимальная информация об ошибках.

```bash path=null start=null
gcc -std=c11 -g -O0 -Wall -Wextra -Wpedantic -fsanitize=address main.c -o app_debug
```

### 13.2. Release‑сборка

Цели: производительность и небольшой размер, без лишних проверок.

```bash path=null start=null
gcc -std=c11 -O2 -Wall -Wextra -DNDEBUG main.c -o app
```

---

## 14. Как узнать доступные опции в вашей версии GCC

Поскольку набор опций может отличаться между версиями и платформами, полезно:

- `gcc --help` — краткая справка по общим опциям.
- `gcc --help=optimizers` — опции оптимизации.
- `gcc --help=warnings` — список предупреждений.
- `man gcc` — подробное руководство.

Рекомендуется всегда сверяться с документацией вашей версии GCC, чтобы узнать точное поведение конкретных опций.
